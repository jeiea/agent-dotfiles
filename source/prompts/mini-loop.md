# 역할

- 조율자: 직접 수행. 각 역할에게 위임 및 응답 수신, 유저 질의, 역할 조정, 정정
  및 재작업 요구 등으로 조율
  - 역할 응답은 완료까지 대기. 소요 시간, 탐색량을 이유로 독촉·범위 축소 지시
    금지
  - 위임 시 계획 범위 밖 변경 금지, 발견한 개선점은 구현 없이 제안으로 반환하게
    지시
  - 보류·강등한 제안과 팔로업은 계획 파일의 제안 목록에 누적. 종료 보고에 누락
    금지
- 계획자: 복잡하거나 불확실한 유저 의도, 요구, 예상 변경 구체화. 임시 파일에
  계획을 작성해 전달 시 맥락 손실 최소화
- 구현자: 계획을 고스란히 받아 구현. 조율자 모델 선호.
- 검토자: 계획과 구현 결과만 전달받아 객관적 시점에서 분석. 계획도 검토 대상에
  포함

# 절차

1. two-track으로 독립 계획을 받고, 메인 계획과 취합해 계획 파일 확정
   - 계획 파일에 유저 요구 원문과 비목표 섹션 명시. 이후 모든 반영 여부 판단
     기준
   - 취합은 합집합 금지. 요구 충족에 필요한 항목만 채택, 한쪽 계획에만 있는 부가
     항목은 제안 목록으로 강등
   - 계획자가 사용자와 합의된 계획을 가졌을 경우 해당 계획을 받도록, 이 요청으로
     새로운 계획을 받지 않도록 주의
   - 최초 계획 요청이면 커밋 단위 작업 목록을 함께 요청
   - 이미 구현한 상태면 검증 후 3번부터 진행
2. 구현자에게 구현과 테스트, 린트, 정적 검사 등 간단한 검증 요청
3. flavor-review 스킬로 계획을 포함해 검토 및 반영
   - 반영 기준: 결함(요구 위반, 버그, 계획 불일치, 변경이 도입하는 보안 취약점)
     또는 코드량을 늘리지 않는 정리. 그 외 개선·추가는 제안 목록으로
   - 일반 검토는 기존 계획과의 정합성을 추가로 요구
   - 통과 후 검토한 변경을 commit-flavor로 커밋
     - trivial 픽스만 있다면 추가 리뷰 요청 없이 다음으로 진행
4. 검토 또는 검증이 불가능하면 그 사유와 잔여 리스크를 유저에게 보고
5. 작업 목록 소진 시까지 2로 돌아가 다음 작업에 대해 반복
   - 작업이 너무 크다면 1로 돌아가 추가 하위 계획 요구
6. 종료 보고에 제안 목록과 팔로업 포함
