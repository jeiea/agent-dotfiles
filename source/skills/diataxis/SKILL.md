# 판별

두 질문으로 유형 결정: 행동 안내 vs 지식 전달? 학습 중 vs 작업 중?

| 유형     | 답하는 질문  | 내용 | 니즈 | 형태        |
| -------- | ------------ | ---- | ---- | ----------- |
| 튜토리얼 | 가르쳐 줄래? | 행동 | 학습 | 수업        |
| 하우투   | 어떻게 하지? | 행동 | 작업 | 단계 나열   |
| 레퍼런스 | 무엇이지?    | 인지 | 작업 | 건조한 기술 |
| 설명     | 왜지?        | 인지 | 학습 | 담론        |

문서 전체뿐 아니라 섹션, 문단, 문장 단위에도 적용

# 유형별 작성

공통: 이탈 내용은 중요하면 알맞은 유형 문서(섹션)로 이동 후 링크, 아니면 삭제

튜토리얼 — 성공 경험으로 배우게 하는 수업

- 시작에 도달점 제시: "이 튜토리얼에서 우리는 X를 만듭니다" ("배울 것입니다"
  금지)
- 할 일 ≠ 배울 것: 익혀야 할 개념, 도구, 행동과의 만남을 경로에 모두 포함
- 매 단계 가시적 결과, 기대 출력 서술: "~가 표시됩니다", "출력은 대략 ~"
- 지나가며 주목할 점 짚기: "~에 주목하세요"
- 단일 경로: 선택지, 대안, 옵션 무시
- 작고 구체적인 단계: 추상, 일반화 대신 이 행동, 이 결과
- 설명 최소화: 한 문장 근거 + 링크
- 안전하고 언제든 재시작, 반복 가능하게 설계. 남은 결함은 유저 관찰로 발견
- 1인칭 복수 "우리"

하우투 — 유능한 유저의 작업 안내

- 도구 조작 나열 아닌 유저 목표, 문제 관점
- 특정 목표로 한정: "웹앱 만드는 법" 같은 열린 주제는 하우투 아님
- 제목에 결과 명시: "X하는 방법" (모호한 명사구 금지)
- 조건 명령형: "X가 필요하면 Y"
- 기초 지식 설명 생략, 완전성보다 실용성 (시작, 끝 적절히 절단)
- 유저 사고, 행동 흐름 따라 순서 배치, 맥락 전환 최소화
- 분기, 판단 허용: 실세계 변형에 적응 가능하게

레퍼런스 — 기계의 중립 기술

- 지시, 해설, 의견 배제. 작동 방식, 올바른 사용법 기술은 허용
- 문서 구조가 제품(코드) 구조를 반영
- 표준 패턴, 열거, 표로 일관되게
- 예시 허용하되 설명으로 발전 금지
- 필요 시 경고: "반드시 X", "C가 아니면 B 금지"

설명 — 주제를 조망하는 이해 지향 담론

- "~에 대하여"를 붙여 성립하는 제목
- 왜에 답변: 설계 결정, 역사, 제약, 맥락, 연결
- 대안 비교, 의견, 관점 허용
- 가상의 "왜?" 질문으로 범위 한정

# 흔한 혼동

- 튜토리얼 vs 하우투: 기초/고급 차이 아닌 학습 경험/작업 지시 차이
  - 튜토리얼: 교사 책임, 통제된 환경
  - 하우투: 유저 책임, 실세계, 예상 밖 상황 대비
- 레퍼런스 vs 설명: 지루한 열거면 레퍼런스, 작업을 떠나 읽을 만하면 설명
- 한 파일에 여러 니즈 혼재 시 유형별 섹션으로 분리, 제목이 유형을 드러내게

# 작업 방식

- 빈 4분류 구조 선행 생성 금지, 개선 누적으로 구조가 안에서 형성
- 반복 단위: 대상 하나 선택 → 유저 니즈와 유형 판별 → 개선 하나 실행 → 반영
  - 반복은 내부 진행 단위, 요청 범위는 완주
- 분류, 분리는 품질 미보장: 정확성, 완전성, 일관성은 별도 검증
