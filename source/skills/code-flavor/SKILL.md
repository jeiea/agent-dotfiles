# ponytail 규칙

- 사용자 요구·합의 우선
  - 미확인 전제나 작업 중 추가한 선택의 요구사항화 금지
- 요구 충족에 필요한 변경·검증만 계획
  - 추가 예외 처리는 생략 시 요구·기존 계약 위반이나 구체적인 중대 피해를 근거로
    포함
  - 오류 전달·안전한 종료로 충분하면 자동 복구·우회는 후속 제안
  - 비목표·작업 분할·구현 상세는 판단에 필요한 경우만 포함
  - 독립적인 정리·개선은 후속 제안
- 최소 수정이 아닌 최소 코드 지향
  - 생략 → 기존 코드 → 표준 라이브러리 → 플랫폼 기능 → 설치된 의존성 → 한 줄 →
    최소 코드 순 고려
  - 중복 제거에 넓은 수정이 필요하면 일회성 해결 대신 제안
- 버그는 모든 호출 경로 확인 후 공통 원인 한 곳에서 수정
- 추측성 수정 금지
  - 우회·완화 시 한계·제거 조건·진단 수단 명시
- 추가보다 삭제, 영리함보다 평범함 선호
  - 하위 호환 코드·미지원 안내도 삭제 우선 고려

# 코드 구성

- 가변 상태 최소화
- 각 부분의 입출력을 명확하고 작게 유지
- 저장소 규칙·언어 제약 안에서 부수효과 임포트 선행
  - 공개 인터페이스 → 구현 상세, 참조 → 피참조 순 배치
- 코드를 되풀이하는 주석 대신 함수 추출 선호
- 코드·테스트에 드러나지 않는 판단 배경·근거·데이터 보존
  - 주석·문서·테스트 이름·커밋 메시지 중 한 곳 선택
  - 작업 경과·폐기 대안은 최종 선택 이해에 필요한 경우만 포함
  - 민감정보 제거·익명화, 로컬 경로는 재현성 고려
- 데이터 흐름·비즈니스 제약·암묵지 파악
  - 의외이거나 작업 단축에 중요한 미기록 발견은 문서화 제안
- 디노 함수는 필수 인자 0–2개와 마지막 선택 인자 객체 선호
- 프로덕션 코드 작성 시 tdd-flavor 확인
  - 일회성·생성 코드·설정 제외
